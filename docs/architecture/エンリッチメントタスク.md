# エンリッチメントタスク

[全体像](../全体像.md) › ③ コンテキスト整備・提供層

エンリッチメントエージェントが対象のデータ資産を分析し、メタデータの追加や変更を提案する仕組み。\
たとえば `email_address` 列に説明がなければ、説明文の追加を提案し、人が承認すると反映される。

## 用語

| 用語 | 意味 |
|---|---|
| enrichment task | エージェントが対象の資産をどう分析するかを定めた設定 |
| enrichment job | バックエンドで動く実行処理 |
| enrichment run | 1 回の実行 |

## 生成されるもの

- テーブルの概要と列の定義
- 業務概念。用語の定義と KPI の計算式
- 列と用語集の定義の対応
- 検証済みの結合条件と、主キー・外部キーなどの関係
- パラメータ付きの SQL の[クエリテンプレート](../glossary/クエリテンプレート.md)

## 実行の流れ

1. オンデマンドまたはスケジュールで実行を始める。
2. シグナルと文書を分析する。
3. 提案を下書きする。
4. SQL の構文を検証し、信頼度のスコアを付ける。評価セットがあれば精度を比べる。
5. 変更を [change request](../glossary/Change-request.md) として保留する。
6. キュレーターが差分を確認して承認する。

承認された内容は、[Context Sets](Context-Sets.md) の中に [overlay の Entry](../glossary/Overlay-entry.md) として保存される。\
BigQuery のリソースに付いている説明は上書きされない。
